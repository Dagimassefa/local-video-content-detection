# Supplying your own evaluation clips

**No NSFW media is committed to this repository, and none should be.** Not as a test fixture, not
as a sample, not base64-encoded in a test file. That is a deliberate constraint, and it shapes how
this project is tested.

## What that means for verification

The two halves of "does it work" are verified differently:

| What is being verified | How |
| --- | --- |
| **Mechanics** - decode, sampling, budgets, dedupe, aggregation, mitigation UI, performance | Synthetic clips generated by `npm run fixtures`, driven end-to-end by `npm run bench`. Fully reproducible, no media in git. |
| **Decision logic** - thresholds, persistence gating, confidence calibration, segment merging | 139 unit tests over `src/core`. These take synthetic class distributions as input, so they can exercise the positive path exhaustively without any image data at all. |
| **Classification accuracy on real content** | Clips you provide locally. Never committed. |

The consequence worth stating plainly: **the accuracy of the model on real inappropriate content is
not measured by anything in this repository.** The numbers in `docs/04-benchmarks.md` are throughput
and latency, not precision and recall. Treating them as evidence of detection quality would be a
misreading.

## Adding your own clips

Drop files into this directory. Anything here is git-ignored except this README.

```
public/samples/
  positive-01.mp4
  positive-02.mp4
  negative-01.mp4
```

Then either load them through the UI, or point the benchmark harness at them:

```bash
node scripts/bench.mjs --only=positive-01.mp4     # reads from fixtures/, so copy or symlink
```

## Safe negative-set sources

Public-domain clips, useful for checking the false-positive rate on ordinary footage:

- **Big Buck Bunny** / **Sintel** / **Tears of Steel** - Blender Foundation, CC-BY
- **Pexels** and **Pixabay** video libraries - free licence, plenty of ordinary human footage
- Any footage you shot yourself

Worth testing specifically, because these are where the model is known to produce false positives
(see `docs/05-limitations-and-production-path.md`):

- beach and swimwear footage
- medical or dermatological content
- classical art, sculpture, life drawing
- breastfeeding
- close-up skin tones, and macro footage in general
- animation and illustration, which the `Drawing`/`Hentai` classes handle poorly at the boundary

## A note on the strongest test

The most informative thing you can do with a prototype like this is run it over a set of clips where
you already know the answer, and look at the *distribution* of scores rather than the verdicts. The
per-frame class probabilities are all exposed on the timeline (hover any tick), which makes it
straightforward to see whether a wrong verdict came from a genuinely wrong model output or from a
threshold that does not match your content.
